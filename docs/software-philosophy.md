# 软件哲学：选择性继承

挑选判据：一条规则被什么问题逼出来的，那个问题在这儿存不存在。失效的教条都是脱离原始问题后还在被执行。

## 0. 自己的标准

1. 拒绝"静默失败"，而非"失败"——要的不是不出错，是出错时能知道。
2. 按机制拒绝：先看这个建议是谁在说、为什么这么说，再看内容。
3. 验收对象是下一个读到的人，不是当下的正确性。
4. 判断必须可测、可证伪；拒绝的当下写下预测，事后对账。
5. 立场不是财产，出现更好的框架就换。

## 1. 前提：程序不是代码

- 程序的本体是程序员脑中"代码如何对应现实"的理论；源码是有损投影。（Naur, *Programming as Theory Building*, 1985）
- 文档无法完整传递理论，只能传递结论。
- 团队散了程序就死了，即使源码完好。
- 重写冲动不是懒惰，是接手者重建理论的唯一手段；代价是丢掉所有没写下来的部分。

## 2. 复杂度来源

- 首要来源是**状态**，其次控制流，第三代码量。纯函数测输入空间，有状态对象测输入空间 × 状态空间。（*Out of the Tar Pit*, 2006）
- 分离本质状态、本质逻辑、偶然状态、偶然控制流，死盯第一项大小。
- **Simple ≠ Easy**：simple 是客观的（不缠绕），easy 是主观的（手边熟悉）。（Hickey, *Simple Made Easy*, 2011）
- 可执行问句：这个决定把哪两件本来能分开的事绑在了一起（complect）。
- **模块价值 = 功能量 ÷ 接口复杂度**。深模块用简单接口藏大量实现；浅模块（薄包装）净价值为负。（Ousterhout, *APOSD*, 2018）
- 反对 classitis 与"函数不超过 N 行"：切成五段就是五个新接口 + 五处跳转。
- **信息泄漏**：同一设计决策散布在多个模块。比重复更糟——重复看得见，泄漏看不见。
- **战术龙卷风**：飞快出活、留下残骸、且被组织奖励的人。坏结构持续再生产的激励解释。
- 复杂度在演化中必然增加，除非**专门做工作**降低它。重构是独立预算项，不排期等于不存在。（Lehman 第二定律）
- 评价新工具的第一把尺：减的是**本质复杂度**还是**偶然复杂度**。偶然的大头已被吃掉，收益有上限；声称减本质的，多半在挪。（Brooks, *No Silver Bullet*, 1986）

## 3. 边界

- 模块边界藏**易变的设计决策**，不照流程步骤切。用法：先列未来三年最可能变的五件事，边界穿过它们。（Parnas, 1972）
- 功能只有在掌握全部上下文的端点上才能完整正确实现；底层再做一遍要么冗余要么错。判断校验/重试/加密该放哪层的唯一非情绪化依据。（Saltzer, Reed, Clark, 1984）
- **Hyrum 定律**：用户足够多时，接口所有可观测行为都会被依赖，无论契约怎么写。写下的契约不是真正的契约。对策：主动随机化不想被依赖的行为（如 Go map 迭代顺序），或承认它已是 API。
- **最小权力原则**：选能解决问题的最弱表达力语言，越弱越可分析。配置该声明式、不该嵌脚本引擎的正式论证。（Berners-Lee）
- **Conway 定律**：系统结构长成沟通结构的形状。推论：改不动架构时，先看是不是在改错对象。

## 4. 失败

- 错误不得静默通过；除非**显式**压制。（PEP 20）
- 错误处理代码是覆盖最差的代码——只在罕见路径跑，bug 存活最久。
- 解法：把错误处理抽离业务代码，集中到监督树，恢复动作只保留重启一种，于是只有一条恢复路径需要测。（Erlang/OTP, Armstrong 2003）
- 生产故障多为瞬态（Heisenbug），这**正是重启有效的原因**，不是掩盖。（Gray, 1985）
- 复杂系统**永远运行在降级模式**——它总有部分是坏的。既然必然带伤运行，唯一防线是知道哪儿在带伤。（Cook, *How Complex Systems Fail*, 1998）
- 灾难需要多个失败共同发生，单点从不足以致命。
- 事后归因于"根本原因"在方法论上是错的——那是叙事需求，不是分析结果。
- **反向条款**：处理异常的最好办法是设计让该情况不成为异常的 API。（Ousterhout：define errors out of existence）
  - 分界线：语义上真正未定义的输入必须炸；语义上有唯一合理解释的边界情况不该炸。
  - 例：Unix 允许删除已打开的文件；`substring` 越界钳到合法区间优于抛异常。
  - 大量异常属于后者，是把决策成本转嫁给每个调用方——每个调用点重写同样的 try/catch，即信息泄漏。

## 5. 时间与下一个人

- 调试比写代码难一倍；写时用尽聪明，按定义就不够聪明去调它。（Kernighan, 1974）
- **技术债原意**：债不是烂代码，是**代码与当前理解之间的落差**。理解会加深，代码要跟上，否则按过时理论付利息。（Cunningham，本人录像澄清过）
- **预备性重构**：先让改动变容易，再做那个容易的改动。把重构从道德义务变成局部经济决策——道德义务排不进排期，经济决策可以。（Fowler）
- **概念完整性**：宁可要想法连贯但少几个功能的系统，也不要一堆各自不错却互不协调的好点子。所有"要不要加这个特性"的最终裁决权。（Brooks）
- **Chesterton 栅栏**：看不出它为什么在那儿之前，别拆。所有删除倾向的配重，且通常它赢。

## 6. 度量的反面

- **Goodhart**：指标一旦成为目标就不再是好指标。覆盖率是最典型受害者——设成 KPI 得到断言为空的测试。
- 测试只能证明 bug 存在，不能证明不存在；价值在缩小未知区域，取决于用例是否互相独立。一百个相似用例 ≈ 一个。（Dijkstra）
- 比覆盖率诚实的三样：**基于属性的测试**（断言不变量、生成用例）、**故障注入**（唯一能真测恢复路径的手段）、**生产环境保留断言**（断言密度与缺陷密度负相关）。

## 7. 不继承

- **Postel 定律**（宽容接收）已被推翻：固化实现分歧、阻断协议演进、制造安全洞。宽容接收 = 静默失败的制度化。（RFC 9413）
- **Clean Code 函数长度规则**：缺乏实证支持，"抽取到不能再抽"常更难读（见浅模块）。
- **DRY 过度应用**：原意是**知识**不重复，不是**文本**不重复。"重复远比错误的抽象便宜"——错误抽象的修复成本是重复的几十倍，因为要先证明它错，而它已有五个调用方。（Metz）
- **SOLID 只拿一半**：里氏替换、依赖倒置是硬的；单一职责的"变化的原因"不可证伪；开闭原则是投机性泛化的邀请函。
- **GoF 模式**大半是语言缺陷的补丁：23 个里 16 个在动态语言中不可见或消失；Strategy 是函数，Visitor 是模式匹配，Singleton 是换衣服的全局变量。（Norvig, 1996）
- **瀑布是稻草人**：Royce 1970 画完单程瀑布图，紧接着写"上述实现方式有风险且招致失败"。
- **微服务作默认**：Conway 定律武器化。组织没拆先拆系统 = 分布式单体，耦合全在只是变成网络调用，同时失去本地调试和事务。

### 元规则

Knuth（"过早优化"）、Cunningham（技术债）、Royce（瀑布）坏掉的方式相同：**结论流传，前提丢失**。引用一条教条前先找原文。

## 8. 收束

- 活下来的条目收敛于同一件事：把**将来会变的东西**和**将来会看的人**当成一等约束。
- Parnas 藏易变决策、Brooks 保概念完整性、Cunningham 的债是理解与代码的落差、Hyrum 说真实契约由使用者决定、Cook 说系统永远带伤所以要能看见、Naur 说资产是理论而非代码——同一件事的不同侧面。

### 前人没有的一块

- Naur 的悲观前提：理论只能活在人脑里，写下来的东西无法承载它。
- 该前提在高频 AI 协作下部分失效：对面无连续记忆，每个 session 必须从文字记录重建理论，一天重建多次。
- 后果：**写下来的记录第一次成为负载路径本身，而不是负载路径的说明书。**
- 反馈周期从"两年后由离职交接暴露"变成"十分钟内暴露"。
- 因此它同时训练**拒绝的直觉**和**表达**——不可传递的理论会立刻以错误产出的形式打回来。
- 结论：理论传递过去是物理约束（师徒同处一室），现在是一项可练的技能。

## 附：判断力的形成条件

- 训练靠 **决策量 × 后果**，不是决策量。不承担结果的接受/拒绝只是点击。
- 循环有**入场条件**而非天赋闸门：判断力要足够让"拒绝"不随机。跨过则飞快复利，跨不过则一万次等于零次。
- 阈值比想象的低——不需要写得比 AI 好，只需要看得出哪里不对。**审的能力比写的能力便宜。**
- 指标是**校准**而非拒绝率。否得够多在统计上大概率对，但什么也不产出。转化不成具体修改意见的拒绝是带品味口音的噪声。
- 结构性缺陷：**只看得到接受的后果，看不到拒绝的后果**（同招聘中被拒候选人的表现永远缺失）。反馈只从一半流回，且会系统性地让你觉得自己拒对了。
- 唯一解法：拒绝当下写下预测（会在哪儿崩、多久崩），过后对账。写下来才可能被证伪。
